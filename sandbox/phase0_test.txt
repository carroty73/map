목표: 초보자가 간단한 html 파일을 만들어, FastAPI로 서비스를 해보는 실습

Step1. 아주 간단한 test.html 파일을 만든다.
       테스트 용도니까 대충 만든다.

Step2. 서버 정보는 .env에 적는다.
       하드코딩은 github에 올라갈 때 위험하므로 별도로 관리.
       나중에 DB 접속 정보, API 키 등도 여기에 추가.

Step3. 서버에 FTP 데몬(vsftpd 등)과 방화벽/공유기 포트 포워딩이
       미리 설정되어 있어야 한다. 그래야 FTP로 접속 가능.

Step4. test.py를 만든다.
       FastAPI (초 미니) 웹서버.
       "/test"라는 경로를 정의 -> 이 경로로 요청이 오면
       -> test.html 파일을 읽어서 응답해준다.
       8001 포트에서 계속 요청을 기다리는(listen) 프로세스를 띄운다.

Step5. .env의 FTP 정보를 이용해 test.html, test.py를 서버로 업로드한다.

Step6. 서버에 접속해서 test.py를 실행한다. (python3 test.py)

Step7. 브라우저에서 192.168.1.3:8001/test (또는 외부 IP:8001/test)로
       접속해 test.html이 잘 보이는지 확인한다.


[참고] Flask와 FastAPI의 차이

Flask (지금 app.py가 쓰는 것)
 - 오래되고 단순한 동기(sync) 프레임워크. 요청 하나하나를 순서대로 처리.
 - 라우트 정의: @app.route("/path")
 - 타입 검증이나 API 문서화는 직접 코드로 만들어야 함.

FastAPI (test.py가 쓰는 것, 프로젝트 방향에서 목표로 하는 백엔드)
 - 비동기(async) 지원 — requests 대신 httpx 같은 걸로 여러 API 호출(Notion, Kakao)을
   동시에 처리하면 훨씬 빨라질 수 있음.
 - 파이썬 타입 힌트 기반으로 요청/응답 데이터를 자동 검증 (Pydantic).
 - /docs에 Swagger 자동 API 문서가 생성됨.
 - 실행하려면 Flask의 내장 서버 대신 uvicorn 같은 ASGI 서버가 필요함
   (test.py에서 uvicorn.run(...) 쓴 이유).
